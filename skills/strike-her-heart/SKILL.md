# Strike Her Heart 实施支持

这是独立 **Strike Her Heart agent** 的实施支持 Skill，不是该 agent 的启动入口，也不是原有“标记／标注”Skill（`$biaozhu`）的别名。独立 agent 由仓库根目录的 `agents/strike-her-heart.toml` 定义，安装后位于 Codex 的 `agents` 目录；`agents/openai.yaml` 只控制本 Skill 的展示。

由 Strike Her Heart agent 读取本技能，或用户显式调用 `$strike-her-heart` 时，把资料和实际界面对应成**原页面上的编号气泡＋右侧可编辑详情**。这是主要交付物；说明文档只能作辅助。按下列方法完成资料读取、授权访问、页面发现、控件识别、说明生成、覆盖层接入和验收，不把操作清单交回用户执行。单独调用本技能不能被报告成已经启动独立 agent。

任务由 Codex 中的独立 agent 接手、选择工具并持续执行。浏览器扩展仅是用户明确选用时的一种可选执行器；不能因收到在线地址或没有项目源码就默认构建、安装扩展，也不能把扩展包交付当作 agent 已运行。先核对当前已有的读取与原页写入能力，缺少写入接口时明确未完成项并继续可独立完成的识别与映射。

## 启动与访问

先读取 [任务记录与续接](references/task-workflow.md)，由 agent 使用 `scripts/task.py` 建立或加载私有任务记录。保持稳定页面 ID、当前修订、已确认的读取／写入能力、真实编号映射、证据与下一步；用户无需操作脚本。工具就绪、页面呈现和交互验收是独立状态，不能相互替代。

向用户展示“接收任务 → 资料与接入 → 发现页面 → 逐控件说明 → 原页标注 → 验收与续接”的工作流。建档后和关键进度变化时由 agent 运行 `task.py workflow --task-dir 私有任务目录`，更新该目录中的 `workflow.html`，给出可打开的本地入口。展示当前修订、生成时间、页面状态、交互检查、业务缺口与下一步；说明它是只读快照，刷新页面不会自动读取新的任务记录。看板辅助理解流程，原页气泡仍是交付主体。

接受 PRD、原型／设计稿、页面截图、系统地址中的一种或多种，沿用当前聊天已提供的资料、登录会话和范围。**没有 PRD 也启动**：先根据实际页面记录可观察事实，业务规则缺口明确显示。只有 PRD 而无原画面时先提取页面清单，并只询问缺少的目标页面入口；不能凭空重建系统冒充原页面。

用户提供系统地址与账号密码并要求进入系统，即授权使用该账号完成本次登录和范围内查看；不再重复索要登录许可。优先复用已登录会话。凭证仅通过登录 UI 或服务正式认证接口使用，不写进 skill、脚本、标注、日志、截图说明、导出文件或版本库。遇到验证码／双重认证时让用户完成该一步，继续独立的资料整理。

先检查目标服务的可用连接器；需要真实页面时使用当前提供的浏览器工具，严格遵守其文档。不得把只读 evaluate 变成注入工具、绕过浏览器策略或通过其他通道接管受限浏览器。登录后查看页面、菜单、页签和只读详情属于本任务；真实提交、删除、审批、付款和对外发送不属于标注的默认范围。危险按钮照常标注，根据资料说明，不为了验证效果点击。

## 全部页面与控件

1. 登记资料版本与实际读取范围，读取 PRD 中相关截图。以用户指定范围为界；未指定时覆盖所给原型或当前账号在该系统可达的业务页面，包含安全可打开的子页、页签、弹窗、菜单和不同可见状态，不扩展到其他产品或组织。
2. 建立页面与状态清单，逐项记为已访问／已标注／未访问及原因。组合 PRD 页面、原型画板、系统导航与实际跳转去重；循环导航不重复爬取。虚拟列表按可核对实例与稳定行键记录，未滚动范围明确列出。
3. 逐页检查按钮、图标按钮、输入框、文本域、选择器、复选框、单选框、开关、日期、上传、链接、页签、菜单项及可操作表格控件，**每个控件独立编号**。标题、提示、状态和业务区块补充页面内容说明，不能用一条区块标注代替内部控件。
4. 控件位置明确而业务说明缺失时仍放气泡；同名控件按页面、父级、页签、行键区分。未访问或未提供的状态不能宣称已完成。具体证据规则见 [信息与证据](references/annotation-evidence.md)。

## 在原页面上呈现

先读 [覆盖层接入与保存](references/runtime.md)，使用随附的 `assets/overlay.js`，复用已有标注数据；无需每次重写前端。

- **有项目源码**：在用户指定项目接入覆盖层，保留真实布局、路由和业务操作；标注入口可开关。按目标框架接入并清理卸载。
- **在线系统／可访问原型**：先确认已有浏览器、连接器或站点正式接口是否提供获授权的原页写入能力，并由 agent 完成可支持的接入与核验。仅有读取能力时明确原页写入缺口，继续识别与待接入映射。用户对本次任务明确选用扩展方案后，才使用随附扩展作为可选执行器；不将其安装或点击操作设为 agent 的默认使用方式。
- **只有原图／只读设计**：使用实际截图或导出画板作为背景制作交互标注，按原图坐标定位；注明为原画面预览。它不能冒充在线系统上的标注，也不能把截图里的表单当真实表单验证。用户坚持在线原页时，继续完成资料与映射，把受限接入明确列为未完成。

覆盖层自动扫描解决控件发现和可见属性提取，**agent 继续结合 PRD、原型和安全观察补全解释**。通过运行时导入接口或其 UI 把逐字段有依据的说明写回相同编号；不要把全部“未说明”的初始气泡当作完成了功能理解。

## 气泡与右侧栏的硬性要求

- 原页面近控件显示 `A-001` 形式的稳定编号；新增、排序、刷新不能重排已有编号。拥挤处错位放置并用连接线指向目标，避免盖住文字、输入值或点击区域。
- 点击多个气泡后，右侧同时列出已打开的详情；每条可关闭，清空列表只收起。详情包括编号、页面／状态、控件名、内容、功能、限制、跳转、字段依据、缺口和修订记录。
- 每个说明字段均可编辑、保存。保存保留原始证据与旧版本，人工修订不能被 AI 重扫静默覆盖。支持按编号口述修改，更新到同一条数据。
- 每字段展示 L1 已实测、L2 页面声明、L3 PRD 依据（直接定义／推断）、L4 模型猜测或未分级。按 [证据规则](references/annotation-evidence.md) 填写 evidenceMeta 的来源与定位；实测另需真实动作、结果、ISO时间。等级是来源方法，待确认／冲突和人工修改独立保留。tested正文变更进入复核；猜测保持待确认；旧有依据不自动升级，混合来源按最弱适用等级标注。
- 使用编号／名称查找和质量筛选定位下一项；计数明确针对当前呈现的范围。四项核心说明优先展示，来源依据按需展开。人工改动不自动清除冲突／复核，只有明确调整证据状态才解除；保存失败必须保留草稿并准确提示，不能标为已保存。
- 集中评审时开启“只看待确认／冲突项”，通过队列及“下一项待复核”定位，不触发业务操作。按已保存状态纳入待确认、冲突、复核与建议，按编号去重；成功保存并解决最后原因才移出。筛选保留未保存草稿，原页气泡仍可定位；空队列仅描述当前呈现范围，证据等级不充当准确率。
- 当前页面／页签只显示所属与公共控件；切换时旧气泡、连线与已打开详情立即退出，各状态草稿独立保存。滚动、缩放、尺寸、路由、弹窗变化后重定位；旧目标无法核对时待复核。
- 覆盖层空白与连接线不拦截事件，原页面仍能点击和输入；仅气泡和侧栏拦截自己的命中区域。关闭后保持原交互。气泡支持键盘与可访问名称，窄屏右栏可收起。

## 保存与验收

任务执行遵守 [状态与转移协议](references/task-workflow.md)：每个阶段具有进入、成功、失败去向及允许下一步。通过 `task.py transition` 记录实际推进；条件缺失为 `blocked`，实际执行失败为 `failed`，用户明确终止为 `cancelled`。恢复、重试与重新打开终态须显式登记，旧证据和历史保留。只按 `status` 返回的有效状态及完成门槛报告结果，不以总结文案、绑定数或已验收页面数自动宣称任务完成。范围内仍有未验收页面、取消页或未解决缺口时不能完成任务。

多页与中断续跑使用 [可恢复执行协议](references/reliable-execution.md) 的页面队列和控件检查点。每次领取前核对当前页面变化，按租约执行和上报；超时、退避及重试上限由记录工具校验，实际浏览器／模型调用仍由 agent 执行。未知副作用和人工认证问题不得自动重放。

身份、逐条结论来源、刷新前后独立验证和操作权限也按 [可恢复执行协议](references/reliable-execution.md) 实施。来源不足的业务结论保持待确认，独立验证不通过不得宣称任务完成；标注网关只约束经它调用的动作，其他继承工具仍须遵守用户授权和风险边界。

agent 在工作区保留任务进度、页面与状态清单、证据、控件映射、人工修订备份和待完成项；复用已有任务目录，不保存凭证。标注本身优先复用目标已有数据层，并按实际执行器说明保存范围。随附 DOM 运行时使用当前站点、当前浏览器的本地存储，另可导出／导入 JSON；这只是该执行器的行为，不代表整个 Codex agent 仅存在于浏览器中。没有稳定 DOM 锚点、自定义控件、跨域 iframe、封闭 Shadow DOM、Canvas 或浏览器内置页面时，列出实际覆盖限制，选择获支持的接入方式逐项补齐。

验收实际原页／原图：逐页可见控件覆盖、多气泡同时打开、逐字段编辑保存和刷新、页签与路由切换、滚动和缩放、窄屏、关闭后原交互、人工编辑在重扫与导入后保留、缺失与冲突显示。未能测试的场景直说，不以结构校验替代交互验证。

将实际快照和检查结果放进任务证据目录，按稳定页面 ID 登记状态。交互验收通过不表示所有业务字段已有来源；缺口与冲突仍独立报告。续接时先读取已有修订，失效的证据或变化的接入能力需要重新核对，不沿用旧 pass 伪装成新版本已验收。

交付先给可打开的页面标注入口、开关和修改方法，再简述页面清单与覆盖、未访问项、冲突／待补充、保存范围、实际验证结果。只报告真正完成的层级：agent 已创建、运行时可用、目标接入完成、全部页面验收通过是不同结论。
