# 信息与证据

标注应让没有读过 PRD 的人能理解这个控件，同时知道每句话从哪里来。按字段分别判断，不能给整条标注一个“AI 已理解”的总状态。

| 字段 | 提取内容 |
| --- | --- |
| 内容 | 文案、展示数据含义、状态、标签、提示、默认显示 |
| 功能 | 用户动作、执行结果、反馈、关联区域和生效条件 |
| 限制 | 必填、长度、格式、范围、数量、权限、禁用条件、失败反馈 |
| 跳转 | 触发条件、目标页面／弹窗／状态、参数、返回路径 |

每个字段分别保存说明、证据分级、确认状态与人工修订。随附运行时以 `fields[field]` 保存文字、
`evidence[field]` 保存依据说明、`evidenceMeta[field]` 保存结构化来源、`fieldStates[field]`
保存待确认／冲突／复核等状态，`manualFields` 和 `revisions` 保存人工归属及历史。

## 证据分级

| 层级 | UI 标识 | 能支持的结论 | 必须记录 |
| --- | --- | --- | --- |
| L1 `tested` | 已实测 | 在指定页面、状态、账号和时间实际执行动作后观察到的结果 | 来源、定位、动作、结果、ISO 时间 |
| L2 `page` | 页面声明 | 当前 DOM、标签、`required`／`maxlength`／`href` 等声明；可读取源码所描述的逻辑 | 来源与具体定位；源码分析明确注明源码 |
| L3 `prd` | PRD 依据 · 直接定义／推断 | PRD 明确规定的预期行为，或从资料推导出的待验证解释 | 文档／版本、章节／需求 ID、`derivation` |
| L4 `guess` | 模型猜测 | 用户确有需要时保留的待验证假设，不作为已确认业务规则 | 明确假设与缺失依据，保持待确认 |
| `unclassified` | 未分级 | 未提供依据，或旧资料不足以确定来源方法 | 保留原文，后续补证据 |

这是证据方法的分级，不是冲突自动裁决规则。一次成功点击不能证明所有角色、时间、后端条件
均成立；PRD 写明但页面未实现的要求也不能被自动抹去。直接定义与推断须分开，不能把推断
伪装为文档原文。`guess` 不用于主动填满未知业务规则，必须显式写成假设并保持待确认。

同一字段含多个来源层级时按最弱的适用层级标记，在依据说明中逐句对应来源；不能用一句
实测结果替其余未经证实的规则取得 L1。只完成源码读取或看到 DOM 属性不会产生 L1。
证据记录完整只是结构门槛，运行时不能独立认证来源、截图或操作记录的真实性。

`tested` 正文变更后，旧动作不自动证明新文字。保留旧来源与历史，将当前状态置为需复核；
原有冲突继续保留。改变分级、润色文字或人工保存均不能自动解决来源冲突。

## 来源核对

准确区分 PRD 定义、界面声称和实际观察：

- PRD：记录文件／URL、版本、章节与段落或需求 ID；截图记录页码／图片名与区域。引用具体支持该结论的短摘录。OCR 只用于定位，关键数字、单位、必填标记及连线对照图像核读。
- 原型：记录文件、画板／节点和明确连线；原型定义不能证明生产环境已实现。
- 运行页面：记录页面与状态、稳定目标锚点、观察时间和实际属性／安全观察动作。`maxlength=20` 支持“前端声明最多 20”，不证明后端接受规则；星号支持“显示必填标记”，不证明空值提交被拦截。
- 安全实测：只记录真正观察到的动作和结果。按钮名“保存”不能自动变成“保存成功返回列表”；`href` 仅支持声明目标，不能声称最终重定向和权限均已验证。
- 用户修订：记录实际指令、涉及编号／字段和版本。编辑文字不是自动解决冲突的确认；明确解决指令才更新冲突状态。

## 结构化记录

下面仅表示结构，不能把示例当成已经发生的实测。只有真实执行过对应动作时才填写 L1：

```json
{
  "level": "tested",
  "source": "任务证据/save-refresh.json",
  "locator": "P-001 / A-009 / #search-name",
  "action": "说明经用户修改后保存，刷新并重新打开同一编号",
  "result": "原编号、修改文字及来源记录均保留",
  "observedAt": "2026-10-27T08:00:00Z",
  "derivation": "explicit"
}
```

L2／L3 需要 `source` 和 `locator`；L1 另需非空 `action`、`result` 和有效 ISO 时间。
PRD 的 `derivation` 只能为 `explicit`（直接定义）或 `inferred`（推断）。来源中的版本号
应写进 `source`，具体段落／控件写进 `locator`。操作、结果及时间不得由模型补造。

编辑时缺少必填证据，保存应提示缺项并保留草稿；外部记录声称高级证据却不完整时，显示未分级
并待复核。查看 [运行时参考](runtime.md) 了解导入、迁移与显示行为。

## 旧数据兼容

旧 `fieldStates.observed` 原意是“页面可见”，只迁移为 L2 页面声明，绝不作为点击实测。
旧 `supported`、`user` 或其他不能确定来源方法的记录保留为未分级，原文、证据说明、编号、
人工修订与冲突状态保留。不能通过旧证据字符串出现“点击”或“PRD”就猜测并提升等级。

缺少 PRD 时，不要把所有功能都留空：可描述可见控件种类、文案、声明的选项、明确链接、界面提示和安全观察到的交互；对不能核实的业务结果写清“未说明，待确认”。不得臆造常见上限、权限、默认值、后端规则或跳转参数。

来源登记保留 `sourceId`、类型、版本、具体定位和已读范围。冲突双方的说法和来源并列，不自行按时间选一方。用户指定新版本替代旧版时保留历史，仅重核受影响字段；无法访问旧页面不能直接视为删除。

页面／控件定位和业务关联是独立信息：目标已找到但 PRD 未说明，仍然显示气泡；PRD 有条目但目标不唯一，进入该页待定位清单。不要将不确定需求贴给恰好同名的按钮。重复行按稳定行键定位，每个可见实例编号独立；排序后不能错绑。

截图模式还需记录原图尺寸、版本与 `[x,y,width,height]` 归一化区域；缩放和留白换算后定位。旧坐标未经验证不挪用到新截图。

页面覆盖表应同时检查 PRD、原型、导航三方：页面／路由、页签／状态、来源、访问结果、发现控件数、已放气泡数、证据完整项、缺口、未访问原因。覆盖率只对明确清单计算，不能把已访问页面当全部系统。
