# 信息与证据

标注应让没有读过 PRD 的人能理解这个控件，同时知道每句话从哪里来。按字段分别判断，不能给整条标注一个“AI 已理解”的总状态。

| 字段 | 提取内容 |
| --- | --- |
| 内容 | 文案、展示数据含义、状态、标签、提示、默认显示 |
| 功能 | 用户动作、执行结果、反馈、关联区域和生效条件 |
| 限制 | 必填、长度、格式、范围、数量、权限、禁用条件、失败反馈 |
| 跳转 | 触发条件、目标页面／弹窗／状态、参数、返回路径 |

对于每个字段保留 `text`、`state`、`evidenceRefs`，以及旧值和修订。字段状态可用：有依据、界面可见、已观察、未说明、冲突待确认、待复核、用户修订。准确区分 PRD 定义、界面声称和实际观察：

- PRD：记录文件／URL、版本、章节与段落或需求 ID；截图记录页码／图片名与区域。引用具体支持该结论的短摘录。OCR 只用于定位，关键数字、单位、必填标记及连线对照图像核读。
- 原型：记录文件、画板／节点和明确连线；原型定义不能证明生产环境已实现。
- 运行页面：记录页面与状态、稳定目标锚点、观察时间和实际属性／安全观察动作。`maxlength=20` 支持“前端声明最多 20”，不证明后端接受规则；星号支持“显示必填标记”，不证明空值提交被拦截。
- 安全实测：只记录真正观察到的动作和结果。按钮名“保存”不能自动变成“保存成功返回列表”；`href` 仅支持声明目标，不能声称最终重定向和权限均已验证。
- 用户修订：记录实际指令、涉及编号／字段和版本。编辑文字不是自动解决冲突的确认；明确解决指令才更新冲突状态。

缺少 PRD 时，不要把所有功能都留空：可描述可见控件种类、文案、声明的选项、明确链接、界面提示和安全观察到的交互；对不能核实的业务结果写清“未说明，待确认”。不得臆造常见上限、权限、默认值、后端规则或跳转参数。

来源登记保留 `sourceId`、类型、版本、具体定位和已读范围。冲突双方的说法和来源并列，不自行按时间选一方。用户指定新版本替代旧版时保留历史，仅重核受影响字段；无法访问旧页面不能直接视为删除。

页面／控件定位和业务关联是独立信息：目标已找到但 PRD 未说明，仍然显示气泡；PRD 有条目但目标不唯一，进入该页待定位清单。不要将不确定需求贴给恰好同名的按钮。重复行按稳定行键定位，每个可见实例编号独立；排序后不能错绑。

截图模式还需记录原图尺寸、版本与 `[x,y,width,height]` 归一化区域；缩放和留白换算后定位。旧坐标未经验证不挪用到新截图。

页面覆盖表应同时检查 PRD、原型、导航三方：页面／路由、页签／状态、来源、访问结果、发现控件数、已放气泡数、证据完整项、缺口、未访问原因。覆盖率只对明确清单计算，不能把已访问页面当全部系统。
